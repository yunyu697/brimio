版本 v1.0 · 2026-11-16 · 本轮只出规范与设计稿，不改 Swift 源码、不改 `DESIGN.md` / `README.md`

## 0. 先给结论

本规范用三条**可推导的规则**处理这次的三个现场，不做逐页调参：

| 现象 | 事实（同版源码实测） | 规则解法 |
| --- | --- | --- |
| 设置页看起来比其它页更贴边 | **所有页内容盒左缘都是 23.0**（到形状几何左缘），到可见侧壁的净间隙 6.0（文件架缩略图行 8.0）。设置页是唯一有**整行填充底色**的页：填充把视觉边界推到内容盒边缘，而文字页的视觉边界停在字形墨迹，天然多出约 1pt 的字面留白。同样的 23，读起来一边是「面贴边」，一边是「字有呼吸」 | §6.6 新增 `FillInset`：**整行持久填充面**（按钮条、状态条）相对内容盒再内缩 **4** → 填充缘 27、宽 254 → 246。推导与适用范围见 §6.6，豁免记为 E7 |
| 设置页最后一行到面板底边有六七十 pt 纯黑 | 页面按「槽位」声明内容高 112（= 4×28），实际渲染只有 74（15+8+15+8+28）；容器仍按 112 撑开，多出的 38pt 变成真空，再叠加 16pt 底部内距 = 54pt（从最后一行字形量约 60.5pt） | §7：`H = 92 + C`，`C` 只由实际渲染的行高与行距相加；内容少于声明值就**收高度**，禁止用比例分配/`Spacer` 把剩余空间摊掉。设置页 204 → 166 / 194 / 222（按子态） |
| 首页空态底部余量 39.0pt、权限被拒 37.0pt（播放中 16.5、计时器 18.5） | 首页四态声明**共用** 56pt 槽位，但空态实际只有 1 行 15、权限被拒与只有播放状态只有 1 行 28，余下的被「垂直居中」摊成上下空白 | §7.2 拆表 + §7.6：首页 **播放中 148 / 只有播放状态 120 / 权限被拒 120 / 空 107**；同页多子态高度差是要求，切换按 §7.6 的六条执行 |

三个现场共用同一句结论：**横向基准只有一个（23），纵向高度只由实际内容推出来**。凡是绕开这两句的写法——页面级内边距、固定槽位、居中摊白、比例分配——都按实现缺陷处理。

## 1. 不可变几何（本规范的地基）

以下数值来自窗口层（`ScreenGeometry` / `NotchHardware` / `NotchShape`），本规范只使用、不修改。

### 1.1 硬件与形状

| 项 | 值 | 说明 |
| --- | --- | --- |
| 硬件禁画矩形 | 179 × 32，屏幕坐标 x 645.5…824.5、y 924…956 | `auxiliaryTopLeftArea` / `auxiliaryTopRightArea` + `safeAreaInsets.top` 反推 |
| 闭合宽 | 183 = 179 + 2 × 2 | 每侧 2pt 抗锯齿/overscan 补偿，闭合形状正好压住硬件带 |
| 闭合高 | 32 | 等于硬件带高 |
| 展开宽基准 | 300 | 首页/设置；宽度只能由内容宽派生（见 §6.4） |
| 展开高 | 92 + 内容高 C，上限 232 | 见 §7 |
| 窗口尺寸 | 316 × 252 | 300 + 2×8 边距；232 + 20 阴影预算 |
| 顶部凹肩切点偏移 t | 展开 19，闭合 6 | 内凹肩曲线的切点偏移量，**不是** `cornerRadius`；约束与推导见 `NotchShape` 文件头 |
| 底部外圆角切点偏移 | 展开 24，闭合 14 | 同上，也不是 `cornerRadius` |
| 阴影 | 展开 0.35 / radius 4 / 下移 2 / 顶部 25% 遮罩；闭合 0 | 方向性阴影，只在下缘与两侧下缘出现 |

形状路径（pt 坐标，`t` 取当前状态，`b` 为底部切点偏移）：

```
M 0,0
Q t,0   t,t
L t,H-b
Q t,H   t+b,H
L W-t-b,H
Q W-t,H W-t,H-b
L W-t,t
Q W-t,0 W,0
Z
```

### 1.2 侧壁：内容盒横向内缩的唯一来源

路径里 `L t,t → L t,H-b` 这一段是**竖直直边**，也就是说形状的侧壁整条都在 `x = t`，不是 `x = 0`。

- 展开态侧壁在 x = 19；
- 闭合态侧壁在 x = 6；
- 形状外侧 0…t 的黑边是肩部曲线的投影区，视觉上属于「屏幕边缘」，不属于内容区。

因此内容盒横向内缩只能写成 `t + 净间隙`，净间隙取 4（与硬件让位同一个常量 `contentGap`）。展开 23、闭合 10。任何 7、8、16 的**页面级**内缩都在这条推导链之外（实测所有页均为 23；7/8 是图标墨迹到侧壁的净间隙，不是内容盒）。

### 1.3 顶部让位

顶部 = 硬件高 32 + 净间隙 4 = 36。含义：chrome 行的第一颗像素落在 y ≥ 36，永远不进硬件带。无刘海外接屏时 `topInset` 回退 16（`PageMetrics` 既有行为），同页高度整体 −20，本规范其余数值不变。

### 1.4 底部

底部内距 16 是**唯一的纯设计量**，不由几何硬推：

- 底部曲线从 `y = H − 24` 开始起弯；内容盒底边在 `y = H − 16`，此处形状内收仅 0.8pt（解析：`y = H − 16` 对应 `s = 1 − √(16/24) = 0.1835`，内收 `24·s² = 0.81pt`），完全在直边段内，不存在裁切风险。
- 留 16 的理由是节奏：顶部让位 36 是硬件约束，底部用最小的一档页面内距收尾，形成「上重下轻」的稳定结束感。这个值不允许按页变化。

## 2. 间距阶梯

### 2.1 档位

4pt 网格。只允许下表的值出现在界面里；**不允许 6 / 10 / 14 / 18 / 20（作为间距）**。

> **决策 D2（2026-11-16，项目所有者拍板）：采纳「4 基网格 + 宽度阶梯」。这是我方决定，不是行业做法。**
> 取证结论：上游四家（Boring Notch / DynamicNotchKit / NotchDrop / Peninsula）都没有 spacing scale，
> 也没有宽度阶梯——闭合宽全部由硬件派生，展开宽是几个孤立固定值（600 与闭合宽无倍数关系，甚至不是 16 的整数倍）。
> 采纳的前提是接受「不许自由调宽」这条产品约束。落点：
> ① 栅格单位 `u = 4`（`DesignSystem.Grid.unit`），所有间距、骨架常量、展开页宽都取 u 的整数倍；
> ② 展开页宽必须来自显式阶梯 `PageMetrics.widthLadder = [228, 248, 300]`，新增页宽要写进这张表；
> ③ 底部余量上限 32pt（16 底距 + 至多一档）。
> 门禁三条对应断言：`every layout constant sits on the 4pt grid` / `expanded widths come from the declared ladder` /
> `bottom margin stays within 16 + one step`。

| Token | 值 | 用途 | 禁止用途 |
| --- | --- | --- | --- |
| `Spacing.none` | 0 | 结构对齐、`HStack` 中显式去掉默认间距 | 视觉留白 |
| `Spacing.xs` | 4 | 同一信息块内相邻两行（摘要两行）、行内图标与文字之间、Tab 命中区之间 | 分隔两个信息组 |
| `Spacing.sm` | 8 | 相邻列表行之间、信息块内部元素之间（封面与文字列、文字列与控件） | 页面内边距 |
| `Spacing.md` | 12 | 块与块之间（chrome → 内容、内容 → 底部操作） | 行距 |
| `Spacing.lg` | 16 | 页面底部内距；独立设置窗口四边 | 行距、块间距 |

### 2.2 派生量（不是间距档位，不得当 gap 复用）

| 名称 | 值 | 推导 |
| --- | --- | --- |
| `contentGap` | 4 | 内容与硬件/侧壁的最小净间隙 |
| 内容盒左/右内缩 `H` | 23（展开）/ 10（闭合） | `t + contentGap` |
| 内容盒顶部内缩 `T` | 36（有刘海）/ 16（无刘海） | `硬件高 32 + contentGap`；无刘海回退 |
| 内容盒底部内距 `B` | 16 | 见 §1.4 |

### 2.3 组合规则

- 相邻两行属于同一信息块 → 4；属于同一列表的不同行 → 8；跨信息块 → 12；页面收尾 → 16。
- 间距只加在相邻元素之间，**不在容器首尾加**（首尾由内容盒负责）。
- 任何「为了对齐而补的 1–3pt」都不允许，改用行盒居中（见 §3.3）。

## 3. 字体阶梯

### 3.1 两个字号、两个行高

| 角色 | 字号 / 行高 | 字重 | 字体族 | 用途 | 单行上限 |
| --- | --- | --- | --- | --- | --- |
| `Typography.title` | 14 / 18 | semibold (600) | rounded | 每页的主信息：曲名、文件名 | 1 行，尾部截断 |
| `Typography.body` | 11 / 15 | regular (400) | default | 副信息、空态说明、按钮文字、列表行、文件大小 | 1 行；空态可 2 行 |

规则：

- 只有两个字号。**禁止 10 / 12 / 13 / 16pt** 的正文；图标尺寸不是字号。
- 字重只有 400 / 600 两档。**禁止 500 / 700 / 800**；需要强调时换颜色层级（§4），不换字重。
- 数字（文件大小、计数）加 `.monospacedDigit()`，字号行高不变。
- 应用名、版本号、页名不上屏（页名由图标选中态表达）。

### 3.2 行盒

- 单行文字必须固定为规范行高（`textLineBox`），否则系统默认行高（约 `size × 1.21`）会让「内容高 + 内边距」与渲染差 1–2pt。
- 行盒公式：`行盒高 = lineHeight`；单行文字在行盒内**垂直居中**。
- 多行（仅首页空态与权限被拒允许 2 行，见 §7.7.4）：`lineSpacing = lineHeight − size × 1.21`，即 11pt → 1.8pt、14pt → 1.1pt。

### 3.3 垂直居中的基准

行内元素（16pt 图标、20pt 图标）在行高内居中，不写 `padding` 凑位置。由此产生的半像素（如 `(32 − 15) / 2 = 8.5`）是合法的，不取整。

## 4. 色彩

面板底色恒为不透明纯黑 `#000000`。所有文字/填充都是白色不同不透明度叠加在黑上，换算成等效色如下（对比度按 WCAG 相对亮度计算，基准 `#000`）：

| Token | 定义 | 等效色 | 对比度 | 用途 | 每页上限 |
| --- | --- | --- | --- | --- | --- |
| `Colors.surface` | `#000`，不透明 | `#000000` | — | 面板/形状填充 | — |
| `Colors.textPrimary` | 白 100% | `#FFFFFF` | 21.0 : 1 | 常驻主信息：曲名、文件名、按钮文字 | 2 条 |
| `Colors.textSecondary` | 白 65% | `#A6A6A6` | 8.63 : 1 | 副信息、空态说明、次级摘要 | 3 条 |
| `Colors.textTertiary` | 白 55% | `#8C8C8C` | 6.25 : 1 | 提示、文件大小、未选中 Tab、禁用说明 | 不限（不得承载唯一信息） |
| `Colors.textDisabled` | 白 35%（本轮新增语义，可直接用 `Color.white.opacity(0.35)`） | `#595959` | 3.0 : 1 | 仅禁用态文字；禁用态不承载信息，允许低于 4.5 : 1 | 仅禁用 |
| `Colors.divider` | 白 12% | `#1F1F1F` | 1.27 : 1 | 1pt 分隔线、虚线框 | — |
| `Colors.badgeFill` | 白 10% | `#1A1A1A` | 1.21 : 1 | Tab 选中块、封面占位、按钮底 | — |
| `Colors.hoverFill` | 白 6%（本轮新增语义） | `#0F0F0F` | 1.10 : 1 | 仅用于可点击行的 hover 底；不可用于常驻块 | — |
| 警示 `#FF9F0A` | 不透明系统橙 | `#FF9F0A` | 10.22 : 1 | 只用于「权限被拒」「需要用户处理」 | 每屏 1 处 |
| 成功 `#30D158` | 不透明系统绿 | `#30D158` | 10.39 : 1 | 只用于「已开启/已授权」的状态点，不配文字 | 每行 1 个 |

黑底上的层级规则：

1. 一页里 `textPrimary` 最多 2 条（曲名 + 文件名，或按钮文字），其余信息降到 65% 或 55%。
2. 55% 不得作为唯一信息载体：文件大小、提示可以；曲名、按钮不行。
3. 禁用态整行（图标 + 文字）统一降到 35%，不允许只降文字。
4. 警示色只表达「需要动作」，不表达「数量为 0」「没有内容」；空态一律用 55% 灰。
5. 禁止渐变、发光、彩色描边；颜色层级只用不透明度与两个状态色。

## 6. 内容盒（所有页面的唯一横向基准）

### 6.1 定义

| 边 | 展开 | 闭合 | 推导 |
| --- | --- | --- | --- |
| 左 | 23 | 10 | `t + 4`（§1.2） |
| 右 | 23 | 10 | 同上 |
| 顶 | 36 | — | `32 + 4`（§1.3） |
| 底 | 16 | — | §1.4 |
| 宽 | `W − 46` | — | W 为形状宽 |

展开态内容盒 = `(23, 36)` 到 `(W − 23, H − 16)`。以 300 宽为例：宽 254，高 `H − 52`。

### 6.2 为什么不是 16 或 19

- 19 是侧壁本身的位置，内容贴到 19 与侧壁零间隙，抗锯齿一糊就粘边；
- 16 小于 19，展开态内容会被形状裁掉 3pt（这正是历史上固定 16 内边距的问题）；
- 23 = 19 + 4 是唯一同时满足「在侧壁内」与「有最小净间隙」的值，且与顶部 36 = 32 + 4 共用同一个 4。

### 6.3 唯一性规则

1. 内容盒由骨架层（`ExpandedContentView` 的 padding）注入**一次**。
2. 页面内部**禁止**再写 `padding(.horizontal)`、负 offset、`frame(width:)` 绕过内容盒；页面只能使用内容盒给出的宽度。
3. 列表行、虚线框的左缘必须与内容盒左缘对齐；图标/文字的**墨迹**允许因为字形或图标自带留白内缩 ≤ 3pt。
4. **整行持久填充面**（按钮条、状态条）的左缘对齐「内容盒 + 4」= 27，见 §6.6。
5. 测量基准：以容器/填充块的左缘为准，**不以字形第一颗墨迹为准**。字形墨迹与内容盒左缘的差超过 3pt 即为实现问题。
6. 右侧同理：可点击区域可以超出内容盒 4pt（命中区扩边），但视觉块不得超出。

### 6.4 宽度派生

宽度不是自由变量，只能由内容宽推出：`W = 内容宽 + 46`。

| 页面 | 内容宽 | 展开宽 W | 说明 |
| --- | --- | --- | --- |
| 首页 | 254 | 300 | 基准宽 |
| 文件架 | 202 | 248 | 行 = 20 图标 + 8 + 126 文件名 + 8 + 40 大小 |
| 计时器 | 182 | 228 | 单行文字，无需 254 |
| 设置 | 254 | 300 | 与首页同宽，便于切换 |

300 是基准宽，不是所有页的强制宽。若产品要求所有页恒定 300，则文件架/计时器分别变宽 52 / 72pt，行内文件名列从 126 变 178、计时器文字区从 182 变 254，高度全部不变。这属于产品取舍，不是规范偏离。

设置页的**文字**仍用 254；**入口按钮**是整行填充面，按 §6.6 内缩 4，宽 246（= 254 − 2×4）。

### 6.5 合法例外

只有 §10 列出的豁免可以偏离内容盒；未列出的任何偏离都按实现缺陷处理。

### 6.6 整行填充面的光学内缩（`FillInset = 4`）

**定义**：横向基准仍是 23。**整行持久填充面**的左/右缘再各自内缩 4，落在 27 / `W − 27`，宽度 `W − 54`。

**适用范围**（同时满足才适用）：

1. 有持久底色或描边的**面**（不是一根线）：白 10% 底、r4、宽度 = 内容盒宽的动作块；
2. 单行成立、整行可点、高度 ≤ 32；
3. 该面上的文字**居中**（不参与左对齐的列布局）。

因此适用：设置页入口按钮「打开播放器设置…」（254 × 28 → 246 × 28，x 27）。

**不适用**，按原规则留在 23：

| 元素 | 理由 |
| --- | --- |
| 文件架行 hover 高亮（6%） | 瞬态且与文件图标列同缘才有扫读价值；hover 时让整行左右移 4pt，视觉噪音大于收益 |
| 文件架空态虚线框（1pt 白 12%，dash 4/4） | 不是「面」：1pt 断线不形成边界质量；且它要与 1 条时的文件行同缘，否则 0↔1 条切换时框和行会左右跳 4pt |
| Tab 选中底（20×20） | 尺寸由 16pt 图标定，本来就不贴边；且 4 个 Tab 的横向节奏由 32 的步长决定 |
| 闭合态徽标、封面、badge | 宽度由内容定，不延伸到内容盒边缘 |

**为什么是 4**（三步都落在数值上）：

1. 字面留白差：11pt 的系统无衬线字体，小写字母左侧 side bearing 约 0.8–1.2pt，14pt semibold 约 1.2–1.5pt。文字块的「视觉边距」实际是 23 + 1.2 ≈ 24.2，填充面是 23.0，差 1.2。
2. 边缘感知差：10% 白在纯黑上的 254 × 28 色块，边界因同时对比（Mach band）向外扩约 0.8–1.5pt；面板侧壁在 x = 19，抗锯齿后的可见边落在 19–20.5。文字页的可见净间隙因此约 6 + 1.2，填充页约 6 − 1.0 ≈ 5。两项合计 2.0–2.7。
3. 落到阶梯：2.0–2.7 向上取到现有最小档 **4**（`Spacing.xs`）。取 2 会得到 250 宽、与摘要行 2pt 的偏心——小到看不出是决定，又大到像实现误差，验收时无法稳定复现；取 8 会让按钮与 23 的图标列形成两条基准，跨页不一致。

**这不是「错位」**：面往内收、墨往外放，是光学对齐的常规做法——两者几何不对齐，视觉才对齐。填充面上的文字仍居中，不因内缩而改字号或行高。

**代价**：按钮宽 246（−8），高度不变；点击命中区仍可扩到 23…277（见 §6.3 第 6 条），只是视觉面收在 27…273。

## 7. 页面高度：内容驱动

### 7.1 公式

```
H = T + 28(chrome) + 12(块间距) + C + B
  = 36 + 28 + 12 + C + 16
  = 92 + C
```

- `C` = 该页当前状态下**实际渲染**的行高之和 + 相邻行之间的间距（只有行与行之间，首尾不加）。
- `T` 无刘海时为 16，此时 `H = 72 + C`，所有页整体 −20。
- 上限 232（`C ≤ 140`）；下限不额外设，最矮的是首页空、计时器空闲（107）。

### 7.2 各页高度

| 页面 / 态 | 内容组成 C | H |
| --- | --- | --- |
| 首页 · 播放中（有/无封面） | 56（封面行） | 148 |
| 首页 · 只有播放状态 | 28（单行，= `Control.md`） | 120 |
| 首页 · 权限被拒 | 28（单行，可点行） | 120 |
| 首页 · 空 | 15（单行 11/15） | 107 |
| 首页 · 空 / 权限被拒（双行档，§7.7） | 30（15 × 2） | 122 |
| 文件架 0 条 / 1 条 | 32 | 124 |
| 文件架 2 条 | 32 + 8 + 32 = 72 | 164 |
| 文件架 3 条 | 32×3 + 8×2 = 112 | 204 |
| 文件架 ≥ 4 条 | 32×3 + 8×3 + 20(露出) = 140 | 232 |
| 计时器（空闲） | 15 | 107 |
| 设置：0 个第三方已开启 | 15 + 4 + 15 + 12 + 28 = 74 | 166 |
| 设置：1 个已开启 | 74 + 8 + 20 = 102 | 194 |
| 设置：≥ 2 个已开启 | 74 + 8 + 20 + 8 + 20 = 130 | 222 |

**相对现状的高度变化**：设置页与首页的三个非播放态都会变。

- 设置页：204 → 166 / 194 / 222（按子态）。
- 首页：播放中 148 不变；只有播放状态 148 → 120；权限被拒 148 → 120（双行档 122）；空 148 → 107（双行档 122）。双行档由文案表声明，不是运行时测量（§7.7.5）。
- 文件架 124/164/204/232、计时器 107 不变。
- 原因：设置页按 4×28 = 112 的槽位声明内容高，实际只有 74，每屏预支 38pt；首页四态共用 56 槽位，空态实际 15（多 41）、权限拒与只有播放状态实际 28（多 28），差额被「垂直居中」摊成上下空白。
- 实测对照：首页空态现状底部余量 39.0（= 21 真空 + 16 底距 + 字形留白）、权限被拒 37.0；按本表收到 107 / 120 后，两处的「内容底 + 16 = H」恒成立。
- 最短页从「仅计时器 107」变成「首页空 107」与「计时器空闲 107」两处；仍不设最小高度保护（见 R4 与 §7.6）。

### 7.3 剩余空间规则（本次底部纯黑的根因条款）

R1. 容器高度必须等于 `92 + C(实际渲染)`。`C` 不允许写成固定槽位（如 `4 × 28`）。

R2. 内容少于容器时，**收高度**。禁止以下三种「填充」：

- 禁止 `Spacer()` / `Spacer(minLength:)` 撑开页面；
- 禁止按比例分配剩余空间（如「剩余 38，上下各 19」）；
- 禁止底部追加 padding 把剩余空间吃掉。

R3. 为什么不是按比例分配：

- 比例分配会让页面顶部内容随状态上下浮动（同一页在空态和满态，曲名/摘要不在同一条基线上）；
- 底部内距会变成 `16 + α`，破坏「唯一底距」；
- 设置页的末行是按钮，把空间推到按钮下方会让按钮悬空，页面没有结束感；收高后按钮距底恒为 16。

R4. 页面高度随内容变化是允许的、也是要求的；状态切换时高度由同一条动画源驱动。不允许为了「不跳高」而预占空行。

R5. 溢出只允许发生在列表页（文件架、设置）：视口必须是整行 + 20pt 露出（见 §8.3），露出部分计入 `C`，属于内容而不是剩余空间。其它页不允许滚动。

R6. 高度断言：`内容底 + 16 = H ± 0.5`；`H = 92 + C ± 0.5`。任一不成立即为实现缺陷。

### 7.4 内容占比自检

内容（chrome + 内容区 + 上下内距）与面板高度相等：首页播放中 148/148、首页空 107/107、首页单行态 120/120、文件架 124/124、计时器 107/107、设置 166/166。**任何页面不允许出现 ≥ 4pt 的无内容黑带**（16pt 底部内距除外）。设置页现状的 54pt 真空、首页空态的 37pt 余量直接违反本条。

### 7.5 两种情形对照（设计稿第 7 节逐格画出）

| --- | --- | --- |
| 页面 | 设置 · 0 个第三方已开启 | 同左 |
| 容器高 H | 166 | 204（固定槽位 112） |
| 实际内容 C | 74 | 74 |
| 内容区末端 | 76 + 74 = 150 | 76 + 74 = 150 |
| 声明内容区末端 | 150 | 76 + 112 = 188 |

| --- | --- | --- |

### 7.6 同一页面不同子态的高度差

**结论：可接受，且是要求。** 同一 tab 内 `H` 随内容变，允许的高度集合：

| 页面 | 高度集合 | 最大跨度 |
| --- | --- | --- |
| 首页 | 148 / 122（双行档） / 120 / 107 | 41 |
| 文件架 | 124 / 164 / 204 / 232 | 108 |
| 计时器 | 107 | 0 |
| 设置 | 166 / 194 / 222 | 56 |

执行规则：

1. **顶部锚定**：形状顶端固定在屏幕硬件带，高度变化只移动下边缘；内容顶恒为 `y = 76`，所以切态时内容不会上下浮动，只有下边缘与最后一行随内容增减。
2. **同一动画源**：高度、宽度、形状曲线用同一条时长与曲线，参数只写在一处；不按高度差改时长，也不给高度单独加弹簧。
3. **同帧提交**：先算好目标态的 `C` 与内容，内容与高度在同一帧提交；禁止「先改高度后换内容」（会出现一帧真空或一帧溢出）。
4. **不设最小高度**：不允许为了防止「跳得太多」把 `H` 卡在一个大于内容的下限——那就是真空。要减小跨度，只能减少真实内容（例如设置页把列表折叠成「另有 N 个」），不能加空白。
5. **两段式禁令**：同一 tab 内切态必须一次动画完成，不允许先缩到中间高度再展开。
6. **越界保护**：`H` 只允许落在 §7.2 表内的值；出现表外高度即为实现缺陷（例如 204 的设置页、148 的首页空态）。

如果产品坚持「首页四态同高 148」，唯一合法做法是把空态与单行态**补真实内容到 C = 56**（不是补空白）——当前没有这样的内容，所以不做。

### 7.7 文本宽度、行数与截断

适用于「单行说明」这类会随文案变长的文本；标题、文件名另见 §8 各模板。

#### 7.7.1 可用文本宽度

| 位置 | 左缘…右缘 | 宽度 | 推导 |
| --- | --- | --- | --- |
| 首页空态说明 | 23…277 | **254** | 内容盒整宽 |
| 首页拒绝态引导文字 | 47…253 | **206** | `254 − 16(图标) − 8(间隙) − 16(箭头) − 8(间隙)` |
| 设置摘要行 / 说明 | 23…277 | **254** | 内容盒整宽 |
| 设置列表行名称 | 47…253 | **206** | 同拒绝态 |

| 文件架文件名 | 51…177 | **126** | 既有行内分配 |
| 计时器文字 | 23…205 | **182** | `228 − 46` |

#### 7.7.2 单行容量（11pt 系统字体）

测算方式：11pt 时 CJK 字宽 = 1.0em = 11pt；拉丁小写平均 0.50–0.55em（5.5–6.05pt）；数字 0.60em；空格 0.28em。理论上限 = `宽度 ÷ 平均字宽`；**保守值再减 2 字**（避头尾、标点挤压、行尾安全区）。

| 宽度 | 纯中文 | 中英混排（约 40% 拉丁） | 纯英文 |
| --- | --- | --- | --- |
| 254 | 21–23 字 | 28–32 字符 | 38–42 字符 |
| 222 | 18–20 字 | 25–28 字符 | 34–37 字符 |
| 206 | 17–19 字 | 24–27 字符 | 31–34 字符 |
| 182 | 15–16 字 | 21–23 字符 | 28–30 字符 |
| 126 | 10–11 字 | 14–16 字符 | 19–21 字符 |

10pt 仅作参考（**不是规范字号**，见 §3.1）：同宽度容量约为上表的 1.1 倍。

#### 7.7.3 行数档位

只有两档，不允许 0 行（空态也要一行）或 3 行：

| 档 | 行盒高 | 行高 | 适用 |
| --- | --- | --- | --- |
| 单行 | 15 | 15 | 默认 |
| 双行 | 30 | 15 × 2 | 仅「整页只有一条说明」的态（首页空、首页被拒） |

- 行间用 `lineSpacing = 1.8` 把每行补齐到 15（§3.2），块总高 30；**不额外加段间距**（15 + 15 = 30）。
- 行高恒为 15（`Typography.body` 的 `lineHeight`），不允许为了塞下两行把行高压到 14。
- 行盒高度 = `15 × n`；**行容器高度 = `max(28, 15 × n)`**：n = 1 时 28（命中区），n = 2 时 30。

#### 7.7.4 各页允许的行数

| 位置 | 允许行数 | 超出时 |
| --- | --- | --- |
| 首页 · 空（说明） | 1 或 2 | 2 行后尾部省略号 |
| 首页 · 权限被拒（引导文字） | 1 或 2 | 2 行后尾部省略号 |
| 首页 · 只有播放状态（主文字） | 1 | 尾部省略号；提示文字先隐藏 |
| 设置 · 摘要行 1 / 2 | 1 | 尾部省略号 |
| 设置 · 列表行名称 | 1 | 尾部省略号 |
| 文件架 · 文件名 | 1 | **中部**省略号（保留扩展名） |
| 入口按钮文字 | 1 | 尾部省略号；按钮高度不变 |

**为什么只有首页的两个「整页单说明」态允许 2 行**：这两页除这一行外没有任何别的信息出口，截断等于把内容砍掉；设置页有列表与按钮作为完整出口，说明只是注释，1 行截断不损失行动；文件架文件名必须保留扩展名，所以用中部截断。

#### 7.7.5 高度：档位由文案表声明，不由实测决定

| 页面 / 态 | 单行档 | 双行档 |
| --- | --- | --- |
| 首页 · 空 | C 15 → **107** | C 30 → **122** |
| 首页 · 权限被拒 | C 28 → **120** | C 30 → **122** |
| 设置（摘要行 2 恒 1 行） | C 74 → 166 | 不适用 |

- 每个态的文案在**文案表**里声明「单行档 / 双行档」，实现按声明取 `C`；不得在运行时测量文本再回写高度。
- 声明必须与实际渲染一致：验收时量实际行数，声明的档位与实际不符即为缺陷（单行档长到 2 行 = 文字被裁；双行档只有 1 行 = 底部多 15pt 真空）。
- 双行档的 122 是**表内合法高度**，进 §7.6 的高度集合：首页 = `{148, 122, 120, 107}`。

#### 7.7.6 截断写法

- 尾部省略号：单字符 `…`（U+2026），不是三个点；省略号贴住最后一行行尾，不留额外间隙。
- 双行档在第 2 行行尾截断，第 1 行必须排满，不允许在第 1 行留白换取「整齐」。
- 中部省略号只用于文件名/路径：保留首 6–8 字符与扩展名（`项目方案….key`）。
- 省略号不得截掉动作主体：`允许控制音乐，去系统设置开启` 这类指令句，宁可行数不够也要保留「去系统设置开启」的动词部分——必要时改写文案，不靠截断默认过关。

#### 7.7.7 禁止

| 禁止 | 理由 |
| --- | --- |
| `minimumScaleFactor` / 动态缩字号（含旧稿 `最小缩放 0.9`） | 11pt × 0.9 = 9.9pt，低于最小可读档；同页两处文字会得到不同字号，字号阶梯失效 |
| 按实测字数/行数回写窗口高度 | 每帧可能触发一次重排，面板抖动；与 §7.6「内容与高度同帧提交」冲突 |
| 3 行及以上 | `C` 再 +15 会挤掉 chrome 的视觉权重；300pt 宽下 3 行已不适合「一眼信息」 |
| 把按钮/箭头折到第 2 行 | 可点元素跨行导致误触，命中区无法用一句 `frame` 表达 |
| 用省略号掩盖必要信息（权限名、动作） | 用户看不到要做什么，等于没有说明 |
| 为了对齐给两行文案补半行留白 | 违反 R1–R4，真空换整齐 |

### 11.2 验收断言（2x 截图逐条量）

1. 内容盒左缘距形状左缘 = 23 ± 0.5；右缘同理（以行容器/虚线框的左缘为准）。
2. chrome 首像素 y ≥ 36；内容顶 = 76 ± 0.5。
3. `H = 92 + C ± 0.5`；设置页 `H ∈ {166, 194, 222}`；首页 `H ∈ {148, 122, 120, 107}`。
3b. 双行档：实际渲染 2 行、行盒各 15、第 2 行行尾为 `…`；单行档实测不得超过 1 行。声明档位与实际行数不符即为缺陷（§7.7.5）。
4. 内容底到形状底 = 16 ± 0.5（以最后一行的 frame 为准，不以字形为准）。
5. 页面内任意连续无内容黑带 ≤ 16pt（列表露出区除外）。
6. 设置页摘要行左缘 = 23，入口按钮左缘 = 27（差 4）；两者右缘分别 277 / 273。

### 11.3 禁止清单

- 在页面视图里写 `padding(.horizontal, 7/8/16)`、`offset(x:)` 改变横向基准；
- 在 `ExpandedItem` 里给页面写固定的 `contentHeight` 槽位（如 4×28）；

## 12. 参考与取舍

对照了多款成熟刘海应用的做法，只取规则，不取代码与数值：

| 产品 | 取的做法 | 不取的部分 |
| --- | --- | --- |
| Boring Notch（开源） | 内容横向内缩跟随形状侧壁（侧壁 + 净间隙，不写死 padding） | 其「多状态固定同高」：媒体页四态共用一个槽位，正是本规范要消除的居中留白；固定 padding 数值也与本机几何不匹配 |
| NotchNook | 面板只放摘要/入口，详细设置外置窗口；文件架用「半行露出」提示可滚动 | 常驻多枚小组件会让高度膨胀 |
| Alcove | 空态收高、不留空槽；状态用图标与颜色表达，不用文字标签 | 装饰性图标底 |
| Loop | 闭合态只承载一枚 20pt 徽标；主面板信息分级严格 | 径向菜单与 HUD 的尺寸体系 |
| Peninsula | 列表页固定行高 + 20pt 露出作为唯一溢出线索 | 通知流的多段结构 |

取舍结论：

1. 面板是「一眼信息」，不是桌面小组件板；常驻信息每页不超过 2 条。
2. 高度永远跟着内容走，空态收高比留白更诚实。
3. 设置类内容只放摘要与入口，避免面板承担完整设置界面。
4. 横向基准只有一个，任何页面都不允许自建一套。
5. 文字与填充面用同一内容盒，但填充面要比文字多收一档（§6.6）——面是边界，墨是留白，光学对齐允许几何错开。
6. 高度是结果不是容器：先有真实内容，再有高度；没有内容就不预留高度。

## 附录 A：底部 16pt 的几何校核

底部曲线（三次形式，控制点按方区边长的 1/3 与 2/3 分配）：`P0 = (t, H−24)`，`C1 = (t, H−8)`，`C2 = (t+8, H)`，`P3 = (t+24, H)`。

参数化：`x(s) = t + 24s²`，`y(s) = H − 24(1−s)²`。

令 `y = H − 16`：`(1−s)² = 16/24 = 0.6667`，`s = 0.1835`，`x − t = 24 × 0.0337 = 0.81pt`。

即内容盒底边所在高度，形状只比侧壁多内收 0.81pt，16pt 底部内距不会碰到曲线；真正需要担心曲线的位置是最后 8pt（内收 2.3pt）与最后 4pt（内收 5.2pt），内容盒都不到那里。

## 附录 B：设置页现状的 54pt 是怎麼算出来的

- 声明内容高：`4 × 28 = 112`（`ExpandedItem.players.contentHeight`）。
- 实际内容：`15 + 8 + 15 + 8 + 28 = 74`（两行 body + 一个 28pt 按钮）。
- 容器仍按 112 高：底部真空 `112 − 74 = 38`。
- 再加页面底部内距 16：按钮框下沿到面板底 = `38 + 16 = 54`。
- 按钮内文字 15pt，居中后字形底再高 6.5pt：最后一行字形到面板底 ≈ `54 + 6.5 = 60.5`，与截图估的「六七十 pt」一致。

本规范把这 38pt 直接删掉：`C = 74`，`H = 92 + 74 = 166`，按钮框下沿到面板底恒为 16。
